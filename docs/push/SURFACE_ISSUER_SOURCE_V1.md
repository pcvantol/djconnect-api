# Source-only surface delegation issuer and principal fences

This successor to draft133/a45fef1 implements the jointly reviewed API-owned issuer proposal. It creates no real approval/key/delegation/credential and performs no provider request, merge, deploy or native action. The public Worker does not import or route this component. Source implementation is not human provisioning approval or operational admission. Existing main9ab24315 and drafts131/132/133 are preserved.

## Actual authority

`createSurfaceIssuer({env,now,admittedProfiles})` consumes server-owned existing operator authentication through `requireAdminAuth` for operator actions only. That helper rejects djci_ and uses DJCONNECT_RELAY_SECRET bearer/HMAC. The factory never reads a secret file or provisions that secret; no global secret belongs in public HA/client code. The request body is bounded before authentication; original raw bytes are reconstructed for HMAC verification. No operator credential or request is persisted.

Operator enrolment records one immutable install/device/owner/grant/source/binding/native-role-policy/public-key/original-expiry tuple. `approval_reference` is an audit reference, not independent evidence of human consent. The root-authenticated operator must actually approve/evaluate that exact policy before any deployment may use it; this source/test fixture is not that approval. Purpose-key signatures prove possession and assertion within that pre-enrolled scope, never human consent. Pairing/djcboot/djci alone cannot create a purpose grant.

Candidate internal POST paths under `/v1/push/surface/issuer/`: `operator/enrol`, `operator/withdraw`, `challenge`, `issue`, `status`, `withdraw`. No browser/cookie/query/fragment/encoded body, duplicate or unknown keys, invalid UTF8 or body over16KiB. Existing HMAC freshness alone is not replay exclusion: operator UUID/digest ledger makes enrolment idempotent and rejects operation reuse across enrol/withdraw. Changed active policy/key/subject requires withdrawal and a fresh explicit delegation. No key replacement or tombstone deletion is implemented.

## Exact source contract and proof

`issuer-wire.ts` owns closed body/policy validation. Operator enrol uses integer contract_version1, purpose surface_push, action enrol, original UUIDv7 operation_id, delegation_id, expected_revision0, approval_reference, install_id, lowerhex64 device/owner/grant/source/binding values, public_key and policy. Public JWK has exactly kty=EC,crv=P-256,x,y; coordinates are canonical base64url32bytes and the runtime must import a valid curve point. Extra/private fields are rejected. Policy has exactly token_role/platform/apns_environment/closed target/activity_profile/external_content_allowed/original_grant_expires_at_ms/max_operations/max_events/max_challenges. Target shape is role-discriminated parent/extension/kind or parent/attributes type. No instance/activity/device token/provider key belongs in enrolment.

Purpose calls use envelope `{payload,signature}` and no Authorization header. Common payload: contract_version1,purpose,action,operation_id,delegation_id,delegation_revision1,key_thumbprint. Issue additionally has challenge_id,nonce,scope_digest. Signature is canonical base64url raw64-byte ES256/P1363. Exact signed bytes are UTF8 of recursively sorted JSON `canonical(["djc-surface-issuer/1","POST",exactPath,payload])`. Key thumbprint is lowercase SHA256 hex of `canonical(["djc-surface-issuer/1","public-key",closedPublicJWK])`, explicitly not RFC7638. No algorithm/DER/ordinary-auth fallback. Public vectors in qualification/surface-push/issuer-public-vectors.json were separately generated with an ephemeral local software key, retaining only its public key, expired synthetic statements and signatures; actual workerd independently verifies their bytes/signatures. Core must adopt these exact vectors/serializer rather than infer a different thumbprint standard.

Scope digest binds version/delegation1/install/device/owner/grant/source/binding/key-thumbprint and the full immutable policy. The API copies policy from the row; issuance cannot supply or widen it. Product limits remain source-proposal limits pending final admission: original grant deadline<=8h, operation counts1..10000, event budget1..1000 and challenge budget1..100. One lifetime successful capability issuance per delegation prevents budget multiplication via new operation IDs. A lost credential cannot be repaired by requesting another challenge/issuance in that delegation. Token rotation inside the existing admitted capability keeps its original scope/deadline.

## Durable challenge/issue/status/withdraw lifecycle

Challenge proof requires the enrolled key and active exact delegation revision. It returns one random256-bit nonce once, stores only its hash, fixes challenge expiry=min(first creation+120s, original UUIDv7+5min, original grant expiry), and consumes a finite durable challenge budget. Duplicate/concurrent/restarted challenge handling cannot disclose another nonce or move the expiry. Lost nonce reply stays unknown. Any explicit reconciliation/new attempt must retain the parent grant limits; no automatic new operation repair is implemented.

Issue verifies the exact signed domain/path/action/nonce/challenge/scope/original operation. A D1 batch atomically rechecks live delegation, original deadlines and single-use challenge, reserves issuance, writes one hash-only djcs_ capability, records outcome and consumes the challenge. Concurrent same/different operation attempts yield at most one lifetime capability for the delegation. Original UUIDv7 execution freshness is rechecked after body/crypto awaits. Actual SQL rollback leaves no partial cap/issuance or consumed challenge. The raw32-random-byte bearer is returned once only to the committed winning claim, after checking the resulting live principal. It is not written to operation outcomes, diagnostics or stored response bodies.

Lost issue reply: signed status uses the original issuance operation_id and returns successfalse, original expires_at_ms, current issued/withdrawn/unknown state, capability_id/scope metadata and credential_state unavailable. It returns no bearer, no refreshed lease and no new credential. Status is the readonly original-window exemption. It verifies the original enrolled key even after grant expiry/withdrawal, so historical reconciliation never restores authority. Core cannot mark a local feature ready from state issued without possessing its still-valid bearer and current local authorization.

Signed withdrawal uses a fresh bounded revoke operation against the same immutable delegation/key. It needs no lost djcs bearer and may remove authority after the grant expired. Operator withdrawal handles lost install keys. One D1 transaction revokes the delegation and all derived capabilities, clears token ciphertext/nonce, retains target fences and closes outstanding challenges. Pending signature/provider authorization cannot pass its subsequent live-row CAS/dispatch check after withdrawal. Already-sent provider traffic cannot be recalled. Restart/key loss never triggers self-enrolment, implicit key regeneration or renewed grant.

## Enforced principal and encrypted-token binding

Migration0010 adds delegation_id/revision, binding_id, grant_binding, source_binding and scope_digest to capabilities and creates the immutable operator/delegation/issuer ledgers plus live-principal view. The view requires the exact active delegation and equal install/device/owner/grant/source/binding/scope/native-role/profile/rights, non-widened budgets and expiry. Old unbound capabilities are excluded, not upgraded. SurfaceStore authentication, first-mutation checks, dispatch checks and receipt checks use this view. Request binding_id must also equal that principal. Token AAD version2 includes the exact delegated authority. This intentionally changes the unadmitted source component; old source tests now use explicit synthetic trusted delegation-row fixtures. Those fixtures are not issuer/approval evidence.
