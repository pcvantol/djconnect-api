# Surface APNs provider authorization source

This is a separately reviewable successor to source-only PR132/a0ff403. It adds `createSurfaceProvider` in `src/surface-push/provider.ts`; public root, ordinary app alerts, capabilities and actual Apple profile admission remain unchanged. The existing handler can consume `provider.authorizeProvider` for WidgetKit or iPhone ActivityKit update/end. Start dispatch remains denied by the original handler.

The factory snapshots exactly the server-owned APNs Team ID, Key ID and PKCS8 private key supplied by its caller. It does not read environment variables/files, provision credentials, mint surface capabilities or perform fetch. No actual provider credential is read in this work. The component accepts a P-256 signing key, imports it non-extractably and produces an ES256 JWT with only `alg`/`kid` header and `iss`/`iat` claims. Raw 64-byte Web Crypto signatures are required; there is no algorithm, key, ordinary-alert or unsigned fallback. Errors expose only a fixed503 code.

Instantiate once for one immutable team/key identity, not on each request. Concurrent first signing and refresh coalesce. The same JWT is reused until50minutes after its original second-rounded issue time, then refreshed. Apple's provider authentication guidance requires ES256, a token at most one hour old and refresh no more often than once every20minutes. A cached token cannot be used when the local clock moves backwards or is nonfinite/fractional/negative. Import/signing delay cannot publish a token already past the50minute boundary.

`close()` permanently retires that instance, rejects pending authorization and clears cached references. It is not remote Apple key revocation, guaranteed secure memory erasure or APNs connection retirement. The caller owns secret provisioning, explicit rotation/retirement and connection policy. The cache is per instance/isolate; it does not prove a cross-isolate/connection20minute refresh rate. A production connection/token lifecycle must be admitted before root integration, including Apple's team/topic/environment connection constraints. No hidden shared state, new credential binding or automatic fallback is introduced here.

This source closes the missing cryptographic authorizer implementation, not operational admission. Surface capability issuer/revoke lifecycle, Core status/ACK adoption, real Apple ContentState and external-content rights, root/provenance, retention/abuse controls and the external browser-CI blocker remain open. Provider200 is not delivery/rendering acceptance. Existing main/PR131/PR132 remain preserved; no deploy/install/provider request was made.
