# Actual browser/receiver/API qualification

This API-owned qualification adds actual Chromium and WebKit execution to the
[Node receiver/API proof](RECEIVER_API_INTEROP_V1.md). It uses the same three
immutable receiver modules and110 installed JOSE/QR package hashes. The actual
receiver's default WebCrypto, visibility, clock and native fetch execute against
the real API five-DO/internal module. Playwright intercepts the request and passes
its exact `postDataBuffer` to the existing closed SDK transport; status, headers
and bytes come from the actual API response. There is no forged ready response,
sender grant, software verifier, submitted destination or native acceptance.

**This route fixture bypasses real HTTP/preflight.** Both engines observed zero
OPTIONS requests. It proves no CORS, TLS, service URL availability, direct-edge
metadata, production UI, installed HA or physical TV acceptance. The minimal
unpublished test page is not a new receiver website or a publication. Current
product root503, unmounted module, sourcewireimplementation.1/wire1,102 baseline
inputs and all22fullservice gatesOPEN remain unchanged. TimerOFF.

## Reproduction and separate network preparation

Use a clean checkout and existing [receiver input procedure](RECEIVER_API_INTEROP_V1.md).
Create a different owned canonical empty0700 directory outside Git for browser
tooling. Its fixture contains only pinned `playwright1.64.1` and `jsqr1.4.0`,
including locked `playwright-core1.64.1`. No root production dependency changes.

```sh
DJC_BROWSER_TOOL_INPUTS="$(mktemp -d)"
chmod 700 "$DJC_BROWSER_TOOL_INPUTS"
node qualification/rendezvous/prepare-browser-interop.mjs "$DJC_BROWSER_TOOL_INPUTS"
npm ci --prefix "$DJC_BROWSER_TOOL_INPUTS" --ignore-scripts --no-audit --no-fund
node "$DJC_BROWSER_TOOL_INPUTS/node_modules/playwright/cli.js" install chromium webkit
node qualification/rendezvous/run-browser-interop.mjs "$DJC_INTEROP_INPUTS" "$DJC_BROWSER_TOOL_INPUTS"
```

The explicit install steps require internet; the runner never downloads browsers
automatically. Existing correctly versioned cached engines can be reused. CI uses
`install --with-deps` on its disposable Ubuntu runner. No Cloudflare action,
account mutation, native signing/installation or persistent browser profile occurs.

Before import, source/fixture/dependency bytes are verified. The shared host-only
package-tree checker preserves the original receiver1MiB file bound and uses an
8MiB bound for browser tooling; exact110 and192-file sets/hash maps remain distinct.
Root/child directory symlinks, unexpected/missing/changed files and hardlinks reject.
Only two exact owned npm metadata symlinks are allowed for the browser tool profile:
`.bin/playwright`→`../playwright/cli.js` and
`.bin/playwright-core`→`../playwright-core/cli.js`. Their target files are hashed;
commands use explicit pinned package paths. Receiver validation allows neither
link. Regular owned `.package-lock.json` remains nonexecuted install metadata.
Four private copied-fixture controls verify changed/missing CLI links, changed
engine metadata and a symlinked package root; each clone passes before corruption.

The root lock's existing esbuild version builds an in-memory IIFE. Its metafile
must contain only the three receiver files and a subset of their110 package
inputs. Playwright and jsQR are host tooling and never enter that browser bundle.

## Four real-engine cases

Each engine runs two isolated contexts in a new headless process, with service
workers blocked and downloads disabled. The default adapter is used without
mocking crypto, time, visibility or fetch. Each case privately decodes the actual
browser's QR matrix using independent jsQR and compares it to the actual API
`qr_payload`. This is not a camera scan, production view or screen-render test.

- **Basic:** create201, independent QR decode, expose, actual cancel200, invalid
  retired context and a second adapter-cancel rejection without another request.
- **Pending:** create201 and QR decode, then two genuine pending200 polls with the
  default real2s spacing. The second poll proves progress after the first response.
  Only then is cancel200 requested; the waiting promise must finish without any
  handoff. Cancellation is not a general network-abort/server-rollback guarantee.

There are exactly four creates, retaining the actual5/IP-minute limit. No clock
acceleration, retry allowance refill, extra QR or positive sender authority is
introduced. Local/session storage lengths are observed as0; no claim about all
storage or physical key erasure follows.

Browser HTTP routing defaults to deny, with one explicit intercepted-denial
control per context before counters reset. Only the private fixed HTML/bundle
and exact API create/poll/cancel POST URLs are admitted. Unexpected OPTIONS are
rejected, never repaired with a fake preflight. Actual Origin/content-type and
absence of cookie/auth/referrer headers are checked. Other fetch options remain
properties of the pinned receiver source, not measurements of network semantics.
Node-global-fetch and workerd-outbound controls/counters are independent. These
are not an OS firewall or a zero-network claim about installation/SDK loopback.

DEBUG/PWDEBUG are removed before importing Playwright; console methods are muted
during browser execution. No screenshots, video, traces, raw page errors, matrix,
QR payload, JWK, claim, nonce, token or destination is emitted. Cases have finite
navigation/poll/evaluation deadlines and always close owned contexts/processes;
the local API is disposed before PASS is printed. Normal cleanup is not secure
physical erasure. Tooling/browser source files and Git bindings are rechecked.

Receipts report actual checkout SHA, source/tool/bundle hashes, engine version and
revision, launch-file hash and fixed case/status/count results. Chromium's launch
executable hash is not its whole installation; WebKit's measured launch file is a
shell wrapper, not the entire engine. Neither certifies a physical TV or installed
Safari. PR-CI can report GitHub's synthetic merge SHA: compare its actual Git tree
to the reviewed candidate, and require separate exact ownmain evidence.

Apple's received40375/PR147 supplies recovery accounting, not exact rawData/profile/
SDK/server readiness. That remains the prerequisite for one jointly ready fresh
