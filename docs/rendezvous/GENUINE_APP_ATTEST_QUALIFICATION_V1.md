## Exact measured development profile

Both attestation and assertion authData contain exactly
`apple_bundle_version_01` (40227,40228 or40230 as appropriate) and
`apple_validation_category_01` as bytes `03000000`. The category is matched to
this exact byte representation; no guessed big-endian number or camelCase alias.
Both kinds use flags0xc0. For assertions, Apple's simplified structure has the
first37 bytes then extensions despite the AT bit; do not feed it to a generic
WebAuthn attested-credential parser. Attestation marker is `appattestdevelop`.

This qualifier deliberately accepts only these captured development builds,
shapes and app policy; it does not silently broaden platform/version/distribution
or production acceptance. Native must compute SHA256 of the exact checked saved
clientData; server must independently hash those same saved bytes. The SDK's
acceptance of31-byte input is not a request-signing API or a reason to accept
caller-provided raw hashes.

## Real unresolved certificate policy

OpenSSL4 strict RFC validation rejects the genuine leaf with **error85, Missing
Authority Key Identifier**, while its ordinary path validator accepts the chain.
The qualifier records both, and does not hide the strict rejection, ignore
critical extensions, trust a supplied root, perform AIA/OCSP fetches or select a
weaker runtime verifier. Basic constraints and intermediate cert-sign usage were
also examined, but these limited controls are **not** a complete substitute for
the adversarial PKI corpus or a qualified path-validation policy.

Before runtime, independently review the exact Apple leaf-AKI compatibility
policy and a maintained Worker-compatible validation stack. Any exception must
be narrow and explicit; do not disable certificate time/path/constraints/critical
